# Сена: правила для работы в проекте

Структура, запуск и устройство описаны в @README.ru.md (только в приватной версии; в публичной — README.md на английском). История решений — HISTORY.md (только в приватной версии, в публичный репозиторий не входит).

## Перед правкой
- Найди нужное место по карте в README. Имя файла агента совпадает с его кодом: `ag_web`, `ag_judge` и так далее.
- Данные (`data/`) личные и в git не попадают. Руками их не трогай без просьбы.
- Бот на Mac не перезапускай и ничего не выкладывай, пока владелец не скажет это отдельной фразой. Приложение Mac (`mac/`) — родное на SwiftUI,
  классические элементы macOS; данные берёт у сервера, свою логику данных туда не тащи. Всё оформление (шрифт, размеры текста и значков,
  отступы, скругления, цвета состояния) — только из `mac/Sources/Style.swift`: в экранах никаких своих `.font(.caption)`, `.padding(10)`,
  `cornerRadius: 8`, `.red`. Разделы собираются из блоков `Block`/`Stat`/`Bar`/`Columns`/`.row` (`Components.swift`): без `Divider`, `Form`,
  `GroupBox`, `HSplitView`, системного `List`; `Table` — только для длинных журналов. Действия экрана — через `.actions { }` в шапку.
  Стандарт элементов: одна высота `Style.Size.controlHeight`, одно скругление `Style.Radius.all`, отступы только `Style.Space.inset/gap/gapSmall`;
  в одном ряду (шапка, строка) элементы стоят напрямую, без вложенных контейнеров со своими отступами. Новая деталь — только через
  готовые `SenaButton`/`Tag`/`Block`, а не своя форма. Проверяет `tests/test_mac_style.py`.
- Если ты Claude, запущенный самой Сеной в её копии (ветка `sena/auto-*`): это безопасный контур саморазвития — правь только в этой копии,
  тесты должны быть зелёными, HISTORY.md дописан (в приватной версии); в рабочий код правка попадёт только по слову владельца.

## Как писать код
- Просто. Не добавляй фреймворки, слои и настройки «на вырост».
- Одно место для одной вещи: пути и модели — в `sena/config.py`, вызовы облачных моделей — в `sena/core/llm.py` (OpenAI; модели Claude он передаёт в `llm_claude.py`),
  моделей на этом Mac — в `sena/core/local.py`, а кто какое дело делает (дом или облако) — в `sena/core/roles.py` (`config.ROLES`),
  чтение и запись файлов и безопасные имена — в `sena/core/store.py`, запросы к внешним источникам данных — в `sena/world/net.py`,
  поиск по памяти (смысл + слова) — только через `sena/memory/index.py`: новая запись, которую Сена должна уметь вспомнить, добавляется в указатель там, где она появляется.
  Записи (люди, правила, цели, задачи, переписка, услышанное, файлы, связи, дела, сигналы, уроки агентов) живут в одной базе через `sena/core/store.py`
  (список — `config.RECORDS`); код, который пишет модель, запускается только через `sena/core/sandbox.py`; ключи — в Связке ключей через
  `sena/core/keychain.py`; инструменты координатора разложены по группам в `sena/agents/ag_sena/toolbox.py` (новый инструмент — под рукой или в группе);
  новый экран для действия в приложениях — панель в `sena/phone/panels.py`, а не код в Android и Mac; поведение мозга проверяет экзамен `sena/exam`.
  Не копируй помощников, а используй готовых.
- Слои зависят только вниз: `core` ← `memory`/`world`/`google` ← `agents` ← `telegram`/`phone` ← `app` (исходящие `telegram.api` и `account` стоят ниже агентов). Проверяет `tests/test_structure.py`.
- Комментарии в коде — по-английски (готовим проект к публикации, его должен понимать любой разработчик). Тексты для модели (подсказки, которые Сена шлёт в LLM) и то, что видит владелец (строки интерфейса, Localizable.strings, сообщения в Телеграм) — остаются по-русски: Сена двуязычная для пользователя, а не для кода. Имена в коде — по-английски. Без эмодзи.
- Платный вызов (модель, картинка, видео, карты) обязан попасть в журнал расходов `sena/core/costs.py`: вызывай только через `llm.py`, `google/media.py`, `world/maps_*`, а для нового сервиса добавь тариф и запись там же.
- Каждое действие пишется в журнал событий `sena/core/events.py` (`events.log`, ошибки — `events.error`): новый канал, агент, фоновое дело или ошибка не должны проходить мимо него; служебное дело оформляй задачей `status.begin(..., service=True)`. Чужую речь и личное содержимое пиши с `private=True` (остаются только размеры).
- Инструмент для модели = описание `tool(...)` + функция с теми же параметрами. Это проверяет `tests/test_tools.py`.
- Умно, а не заплатками: если агент ошибся, правь общий принцип или навык, а не частный случай.

## Проверка и запись
- После правок: `python -m unittest`. Новая логика — новый тест рядом с похожими.
- Экран телефона — родное приложение Android (`android/`), не веб-страница; его собирает и проверяет `./gradlew :app:testDebugUnitTest`. Сервер `python -m sena`
  нужен только при настоящем запуске, для проверки API хватает `python -m sena.phone`. Приложение Mac (`mac/`) — родное, SwiftUI, собирается `mac/build.sh`;
  его логика экрана живёт в Swift, данные — из `sena/phone/desk.py`.
- После законченной доработки допиши HISTORY.md (в приватной версии): что сделано, почему, какие библиотеки.
- Код Claude пишет только через подписку (`claude -p`): Anthropic API для кода не используем никогда. Claude API разрешён только как мозг самой Сены
  и только через `sena/core/llm_claude.py`; ключи называются `SENA_CLAUDE_<роль>_KEY`, не `ANTHROPIC_*` (их не видят ни терминал агента, ни Claude Code).
